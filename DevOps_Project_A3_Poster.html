Problem Statement & Scope

OVERVIEW

Traditional retail lending workflows suffer from opaque processing, lengthy turnaround times, lack of real-time auditability, and no separation between customer submission and underwriting decisioning.

Core Objective: Deliver an enterprise-grade financial tracking portal powered by a fully automated Jenkins CI/CD delivery pipeline, resilient multi-stage Docker packaging, and sub-15s Ansible disaster recovery.
🏛

The 4 SBI Underwriting Pillars

FINTECH ENGINE

Automated credit risk assessment evaluating retail borrower solvency during live intake:

SBI Pillar Threshold Criteria Underwriting Impact
1. CIBIL Score ≥ 750 (Min 650) Credit bureau solvency gate
2. Net Income ≥ ₹20,000 / month Repayment capacity check
3. Applicant Age 21 – 60 Years SBI retail lending boundary
4. Max FOIR ≤ 40% (Max 50%) Fixed Obligation to Income Ratio
[Borrower Submission] ──► Automated Risk Engine ├── CIBIL ≥ 750 & FOIR ≤ 40% ──► ✅ PRE_APPROVED (Fast-Track) ├── CIBIL < 650 or FOIR > 50% ──► ❌ HIGH_RISK_EXCEPTION (Alerts) └── Other criteria met ─────────► ⚠ MANUAL_REVIEW (Underwriting)
Formula: FOIR = (Existing EMIs + Proposed EMI) / Net Income × 100

Dual-Role Portal Architecture

SECURITY • RBAC

Strict separation between public borrower intake and internal banking operations:

👤 End User (Borrower Portal - /my-applications):
  • Self-registration & login with personal credentials.
  • Auto-filled intake form (Name, Email, Phone from profile).
  • My Applications: View and track personal loan status only.
  • Read-Only Tracking: Stage advancement panel is completely hidden from borrowers to prevent privilege escalation.
🛡 Administrator (Officer Console - /dashboard):
  • Global portfolio overview of all bank loan applications.
  • Real-time 4-KPI counters & global search by ID or name.
  • Stage Advancement: KYC Verified → Doc Verified → Underwriting → Approved / Rejected with audit remarks.
  • Alerts Queue (/alerts): Dedicated high-priority review.

Route Security & Tab Isolation

ZERO-TRUST

All internal endpoints are guarded; unauthenticated access is blocked:

Route Permitted Unauthenticated Policy
/login, /register Public Zero internal tabs shown
/dashboard ADMIN Redirect → /login
/my-applications USER Redirect → /login
/apply USER/ADMIN Redirect → /login
/loans/{id} Owner / Admin Redirect → /login
/alerts ADMIN only Redirect → /login (403 for User)
Guaranteed Privacy: Before logging in, navigation tabs (Dashboard, New Application, Alerts) and loan tables are completely hidden from the DOM.

Jenkins Declarative Pipeline

PIPELINE AS CODE

Automated 7-stage CI/CD execution triggered via webhook/polling on Port 8080:

STAGE 1 Checkout SCM (Git main / feature branch) STAGE 2 Unit & Integration Tests (18 JUnit 5 Tests) STAGE 3 Selenium E2E Quality Gate (9 Chrome Journeys) STAGE 4 Multi-Stage Docker Build (Lightweight image) STAGE 5 Continuous Deployment (Port 8081 container) STAGE 6 Actuator Health Verification (HTTP 200 OK)
Strict Quality Gate: If any unit test or Selenium journey fails, the build halts immediately, captures failure screenshots, and prevents deployment.
🔬

Selenium Headless Quality Gate

9 JOURNEYS • ZERO DEFECT

Full automated browser verification executing in Headless Chrome:

  • J1 (Intake): Submits borrower form → verifies LOAN-XXXX on dashboard.
  • J2 (Search): Filters live table by applicant name with instant reset.
  • J3 (Drill-Down): Advances status to DOCUMENT_VERIFIED → audits event.
  • J4 (Alerts): Rejects loan with reason code → verifies alerts queue.
  • J5 (SBI Eligible): CIBIL=820, FOIR ~13% → tags PRE_APPROVED.
  • J6 (SBI Ineligible): CIBIL=580 → auto-tags HIGH_RISK_EXCEPTION.
  • J7 (End-User Portal): Logs in as applicant → personal tracking → verifies read-only stage view.
  • J8 (Admin Management): Logs in as officer → advances stage to APPROVED → logs remarks → accesses alerts.
  • J9 (Route Protection): Asserts unauthenticated visitor is blocked from dashboard/alerts and no tabs are shown.
